# Focus Bear / Late No More calendar dismissal bridge (version 1)

This is a local, advisory alert-suppression contract. It never authorizes access, authenticates an account, or changes calendar events. Both apps must ship the companion implementation before the complete behavior is available.

Focus Bear writes `~/Library/Application Support/FocusBearCalendarBridge/dismissals-v1.json` atomically and posts `io.focusbear.calendar-dismissals.changed.v1` with only a revision UUID. Late No More always reads the fixed path; a notification cannot supply a path or rules. LNM reads at startup, each calendar check, before dispatching each warning, and before delayed speech. Missing, malformed, unsupported, oversized or symlinked snapshots leave warnings enabled.

The Codable schema contains `version`, `revision`, nonsecret `accountID`, and `rules`. A rule contains only EventKit event/calendar identifiers, optional provider external identifier, scope (`day` or `series`), and for day rules an ISO local day and IANA timezone. No title, notes, URL, token or credential is shared. Calendar identity must match, then event ID or nonempty external ID must match. Never match titles. A moved event remains hidden only if its new start falls on the same recorded local day; explicit series hides continue across dates. Unhide removes applicable rules.

The decoder accepts at most 1 MiB, 4096 rules and 1024 UTF-8 bytes per identifier. File reads are bounded even if its size changes. The publisher uses a private directory (0700) and file (0600); the receiving app is the same OS user. This is not a security boundary against other processes owned by that OS user. The shared policy copies are delimited in the two existing compiled Swift files; run `scripts/test-calendar-dismissal-bridge.py --peer-source <other-app-source>` to verify byte parity and synthetic temporary-file tests.

On Focus Bear account change/sign-out, the published rules reset. Repeated assignments to the same account preserve the durable snapshot. The publisher is disabled in the isolated logic test host. LNM may be offline or closed at publication; persistence makes the next launch/check observe it. A fresh notification immediately closes matching existing alerts and stops their verbal loop. Event warning deduplication includes start time so rescheduled occurrences can warn again.

Limitations: existing historical global/series hides are preserved locally and are not guessed into day scopes; users can unhide/re-hide to publish them. Backend-imported legacy IDs cannot be exported without calendar identity metadata. Calendar-provider identifier changes fail open. Exceeding bounds or publication failure preserves the previous snapshot and logs failure; there is no silent truncation. A Focus Bear account switch while Focus Bear is not running cannot be observed. Real cross-app warning/close/relaunch behavior still requires coordinated signed builds and manual QA; pure tests do not claim that validation.
